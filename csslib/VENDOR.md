# csslib - the vendored MIT CSS stack (NetSurf's libraries) + port layer

The real-CSS half of the second-engine programme
(`docs/BROWSER-ENGINE2-PLAN.md` phase 2, series CS0-CS3): libcss's parser +
selection engine upgrading unoweb's cascade in place. unoweb keeps DOM,
HTML and layout; this directory is the engine it consults for computed
styles.

## Two vendor-time GENERATED artifacts (the exception to "no generators ran")

Upstream generates two things at build time that its git does NOT commit;
both were generated ONCE at vendor time with upstream's own tools and are
committed here as ordinary sources. On a version bump, regenerate both:

- `parserutils/src/charset/aliases.inc` - `build/make-aliases.pl
  build/Aliases` from the libparserutils checkout. The generator emits one
  malformed terminator row (`{ , 0, "" }`, from a mibenum-less entry in
  current IANA data; upstream's perl warns and emits it anyway) - patched
  to `{ 0, 0, "" }` here. The ONLY hand edit in the vendored tree.
- `css/src/parse/properties/autogenerated_*.c` (119 files) - upstream's
  `gen_parser` tool (css_property_parser_gen.c, hosted compile) run per
  `^prop:` line of `properties.gen`, exactly as
  `src/parse/properties/Makefile` does. The tool itself is NOT vendored
  (it is a host generator wanting real stdio).

## Port notes (CS1)

- `-DWITHOUT_ICONV_FILTER` - the ONE non-C99 dependency
  (`parserutils/src/input/filter.c` wants iconv) is compile-gated off;
  the built-in UTF-8/UTF-16/fixed-charset codecs remain.
- `-D_ALIGNED=` - upstream quirk: `css/src/stylesheet.h` ends `struct
  css_rule {...} _ALIGNED;` with `_ALIGNED` defined NOWHERE, so every
  including TU tentatively defines a GLOBAL VARIABLE named `_ALIGNED`
  (upstream survives on common-symbol linking; `-fno-common` toolchains
  get 130 multiple-definition errors). Empty-defining it matches what
  upstream builds effectively produce (no alignment attribute ever
  applies).
- `css_port.c` supplies the four libc routines pc64's mini-libc omits:
  `strcasecmp`/`strncasecmp` (compat/strings.h), `bsearch`
  (compat/stdlib.h), `strdup` (compat/string.h).
- compat/ also carries `inttypes.h` and `sys/types.h` (wapcaplet's one
  POSIX include).
- Include paths: the three `include/` dirs public + each lib's `src/` on
  its own compile line; `compat/` FIRST. One flag set, defined in
  `test/build-host-test.sh`, to be mirrored verbatim by the build.sh block
  when CS2 wires it in.

## Tests (CS1)

    sh csslib/test/build-host-test.sh && ./csslib/test/build/css_host_test.exe

The whole stack (320 objects) freestanding-compiled and host-linked:
parse -> cascade -> computed style, 8 checks (keyword/hex/rgb() colors,
grouped selectors, later-rule cascade order, unmatched->initial, display,
@media filtering). Green on mingw (LLP64, the kernel's compiler) and on
linux gcc with ASan+UBSan (`CC=gcc SAN="-fsanitize=address,undefined
-U__linux__ -U__gnu_linux__ -U__GLIBC__" sh csslib/test/build-host-test.sh`).
NOTE the select-handler scaffolding in `test/` is adapted from libcss's
`examples/example1.c` (MIT): `css_test_decls.inc` + `css_test_handlers.inc`
are mechanical extracts, re-extractable on a bump. An element no rule
matches computes the property's INITIAL value (transparent color, not
INHERIT as the old example printed) - the UA default sheet is CS2's job.
